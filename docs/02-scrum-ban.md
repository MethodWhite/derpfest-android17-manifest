# ScrumBan

## Flujo

`Backlog → Ready → In progress → Review → Validation → Done`

Bloqueos salen a `Blocked` con causa, impacto, responsable y próximo experimento.

## WIP limits

| Columna | Límite |
|---|---:|
| In progress | 2 |
| Review | 2 |
| Validation | 1 |

## Cadencias

- Refinamiento: revisar prioridades, riesgos y criterios de aceptación.
- Planificación semanal: seleccionar trabajo que cabe en WIP.
- Revisión: demo de build, logs o documentación.
- Retrospectiva: una mejora de proceso accionable.

## Priorización

P0 seguridad/boot roto; P1 build o función principal; P2 calidad/mantenibilidad; P3 mejora cosmética. Todo trabajo debe indicar impacto y riesgo.
